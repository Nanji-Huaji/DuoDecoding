# CUDA Graph 集成结项报告（2026-09-14）

## 结论：**不采用** ✗

配对 A/B（同一干净窗口、交替顺序、唯一变量 `--use_cuda_graph`、N=40、temp 0）：

| 指标 | eager | CUDA Graph | 判定 |
|---|---|---|---|
| GSM8K 准确率 | 0.25 (10/40) | **0.25 (10/40)** | ✓ 一致 |
| 吞吐 | **11.40 tok/s** | 9.54 tok/s | ✗ **慢 16%** |
| 68M 草稿计算 | 10.29 s | **18.50 s** | ✗ 1.8× 更慢 |
| 1.1B 草稿计算 | 99.98 s | **183.33 s** | ✗ 1.8× 更慢 |
| 逐 token 恒等 | — | 40 样本中 **1 个不同** | ✗ 不是恒等 |
| 墙钟稳定性 | 4:55 / 5:05 | 6:25 / 6:23 | ✓ 更稳但更慢 |

## 为什么亏

1. **图被每个样本重新捕获一次** ✗ —— `adaptive_tridecoding` 按样本重建三个缓存
   （日志里 `[cuda-graph] 已启用图回放` 出现 80 次 = 40 样本 × 2 缓存）。
   捕获开销实测约 534 ms/样本（13B），但**这不是主因**（80 次捕获共约 29 s，
   解释不了 90 s 的差距）—— 真根因见下面第 3 条。
2. **不是逐 token 恒等** ✗ —— bf16 下图回放与 eager 有约 1% 的 logits 差异
   （组件级测试早就测到：1.1B |Δlogits| 0.938%），在 40 个样本里有 1 个
   在第 123 个 token 处翻转，进而改变接受模式与各级前向次数。
   准确率恰好没受影响，但"逐 token 恒等"的说法**不成立**。
3. **（后续才查明的真根因 ✗✗）eager 回退踩在 StaticCache 上** —— 真实管线里
   1.1B 每轮只有 4.3 次前向（5392/1249，不是 γ2=16 次单步），主体是多 token
   整段前向 ⇒ `new_len > 1` 无法进图 ⇒ 走 eager 回退 ⇒ 缓存仍是 StaticCache
   ⇒ 拿不到图收益还付了 StaticCache 的代价 ⇒ 1.1B 单次 18.50 → 34.01 ms
   （慢 1.84×），68M 同样 5.42 → 10.07 ms（慢 1.86×）。曾假设"StaticCache
   按 max_length 全量算注意力"并用 384~896 五档扫描验证 —— **被推翻**
   （图在所有档位都更快且与 max_length 无关）。详细过程见
   `docs/perf_investigation_log.md` 阶段四。

## 什么情况下值得再试

两条路（见 `docs/perf_investigation_log.md`）：
1. **缓存跨样本复用** —— 消除每样本 534 ms 的捕获开销；
2. **把多 token 前向拆成单步**（更干净）—— 图路径只吃 `new_len == 1`，拆开后
   没有回退，微基准的 2.05× 才能兑现。但端到端上限仍是**约 24-25%**（通信+排队
   97 ms/轮不受图影响），优先级不高。

> **2026-09-16 更新**：上述两条已合并实施为**定长 padding 验证图**方案
> （`docs/verify_graph_fix.md`）——"拆单步"对验证前向被证明是负优化（13B 拆步
> 7× 恶化），改为 (1,K) padding 图 + StaticCache 原地 reset 跨样本复用 + 去逐前向
> `.item()` 同步。等价性测试已过（`scripts/test_graph_verify.py`），端到端配对
> A/B 结果在 `exp/vg_*`。

## 修过的两个真 bug（记录）

1. **接线漏点** ✗：`adaptive_tridecoding` 用共享字典 `cache_kwargs` 构造三个缓存，
   按 `KVCacheModel(..., draft_top_k, ...)` 的字面形式写正则会全部漏掉。
2. **长度追踪不同步** ✗：图模式下缓存是预分配的 `StaticCache`，回滚只改
   `runner.nnz`，而 (a) `_prepare_generation_inputs` 仍以 StaticCache 的
   内部计数为 `cache_start`，(b) eager 回退（`new_len > 1`）不会推进 `nnz`。
   两者叠加导致 KV 写到错位偏移、下一轮把已在缓存里的 token 重新喂一遍，
   表现为 `prob_history` 越界（`n1=354` 而 `len=341`，差 `gamma2+1`）。
   修法：图模式下以 `_current_seq_len` 为权威，并在 eager 回退后把 `nnz` 对齐。

## 方法论教训

微基准 2.14× **推不出**端到端有效 ✗。第一次配对就抓到"图根本没接上"
（1.1B 计算 102→105 s 纹丝不动）；修好接线后第二次配对才得到真实结论：
**慢 16% 且非恒等**。任何"优化生效"的结论都必须用真实流水线的配对实验确认，
并同时检查**确定性指标**（前向次数、生成 token 数）与**逐样本输出**。
