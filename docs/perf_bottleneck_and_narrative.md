## 一、当前性能瓶颈（全部实测，最优配置 thr0.4：24.23 tok/s = 183.5 ms/轮）

| # | 成分 | ms/轮 | 占比 | 性质 | 已知修复 |
|---|---|---|---|---|---|
| 1 | 虚拟排队（batch_delay 50ms/轮）| 50 | 27% | 记账 | 轮数∝1/tok-fwd |
| 2 | 虚拟 NTT（per_round 一次）| 50 | 27% | 记账 | 同上 |
| 3 | 13B-4bit 验证前向 | ~60 | 33% | 真实 | bnb 距 8.5ms 地板差 7×；Marlin 级 ~15ms / bf16 42.6ms |
| 4 | 1.1B + 68M + glue | ~23 | 13% | 真实 | 1.1B 已图加速 3×；剩余主要是 glue |
| 5 | 字节传输 | ~0.2 | ≈0 | 记账 | 46Mbps 下 top-300 仅 1.2KB/轮 |

**统一根因：tok/fwd = 4.4（草稿质量天花板）**。轮数 = token/tok-fwd，瓶颈 1/2/3 全部随轮数线性缩放。
几何上界：逐位接受率 α=0.72（实测 72.2% ≈ 论文 Table I 的 72.5%）⇒ 独立上界 3.6，
含相关性实测 4.43。论文 Table V 隐含 6.9 需要 α≈0.855 —— 与它自己的 R_acce(69.5%)
和亲和矩阵(72.5%)矛盾（超界 2×）。

## 三、论文叙事受到的挑战（按危险度排序）

### C1 · Table V 的 Fwd 列与论文自己的数据矛盾 ✗✗（最危险）
R_acce 69.47% + Fwd 1504（6.9 tok/fwd）超几何上界 2.1×；Qwen3 行同样矛盾
（73.75% vs 8.4，上界 3.81）。而 Fig 3 的 trace 参数（草稿 5.265 / 提交 4.712 /
接受 74.3%）与我们的复现（4.43 / 72.2%）一致 ⇒ **Fig 3 与复现互证，Table V 是
outlier**。审稿人用一行算术即可击穿。
→ 修法：Fwd 重新定义为"云验证块数/请求数"并全文一致；或采用复现值（~2373@GSM8K）
并把 6.9 解释为口径差异。

### C2 · 基线计费口径偏松 ✗
论文基线 Tcomm（17.2/14.2/16.1）≈ 各自的纯 NTT 摊销（19.4/17.2/15.7）——
下行全词表分布未按字节计费。诚实口径下基线吞吐掉 25-60%（DSD 12.68 vs 16.37）。
复现者重跑会得到系统性偏低的基线 ⇒ CEE-SD 的相对优势被夸大的质疑。
→ 修法：统一诚实计费重跑基线列（~1 小时 GPU），或论文明确声明"基线传输按
top-k 压缩计"并给两口径。

### C3 · RL(DRA) 价值主张受创 ✗
实测：已训策略 3.88 tok/fwd **劣于**固定阈值 0.4 的 4.43（保守过头）；
且历史诊断"RL≈规则≈固定 γ"（动作空间饱和）仍在。若消融表展示这个对比，
DRA 是负贡献。
→ 修法：域内重训（P1）后 DRA 应 ≥ 固定最优；长期换岗位 A/B（合批控制/精度路由）。

### C4 · 复现性缺口 ✗
论文未写明：CEE-SD 的 γ、NTT 50 vs 76.3、通信计费模式、Table VII 的 N
（26.84 不可能来自 N=80 粒度）。我们花了 9 个探针才逼近。Fig 3 的 replay
算术与 trace 文件未归档。
→ 修法：reproducibility 附录（配置全部已固化在 `scripts/align_paper_t5_gsm8k.sh`
等），Fig 3 脚本化。

### C5 · opportunistic 陷阱（内部一致性）⚠
`cee_sd_opportunistic` 恰好复现论文 Thr 19.34/Cloud$ 0.61（vs 19.50/0.61）但准确率
崩到 0.0625。若当年 Table V 混入此模式，Table VII 的 26.84 无法同时成立——
两张表只能保一张。当前无损路径（0.2375≈0.25，78/80 逐位稳定）只能兑现 Table VII。

### 站得住的部分 ✓
- CEE-SD 主行超额复现：Thr 24.23 / Cloud$ 0.49 / R_acce 72.2（vs 19.50/0.61/69.5），
  叠加了本会话的 CUDA Graph 1.21×；
- 无损性质成立：0.2375 vs 0.25 = 1 个样本的 bf16 漂移，γ5/γ16 逐位一致 78/80；
- 边缘过滤机制有效：R_acce 72.2 vs DSD 裸亲和 60.6（方向与论文动机一致）;
- Fig 3 伪造测试方向健康：compute-only、trace 与复现一致（只需归档）；
- 架构增益（Table VI）未受本次审查影响（未重测，如实标注）。

## 四、一句话总结

性能上：**一个根因（tok/fwd=4.4 的草稿质量）锁死 84% 的轮预算**，kernel 是第二瓶颈；
叙事上：**方法行和精度表站得住，Fwd 列和基线计费两处会被算术击穿**，RL 需要域内
重训 + 换岗位才能留在论文里。P0 的两件半日工作（口径修复 + Fig 3 归档）应在任何
新实验之前完成。
