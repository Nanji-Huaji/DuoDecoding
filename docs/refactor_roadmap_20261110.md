# DuoDecoding 重构目标与路线图（2026-11-10）

状态：目标和推进方向已经本轮用户问答确认；以下为据此形成的实施方案，不代表业务代码已经修改或已经授权启动 GPU 实验。

审查基点：`fdfd27a7bb71d99d3465f08fc3f869db7f5fef70`。原工作区仅有两个未跟踪 HTML 报告，本轮未修改它们。本文是本轮唯一新增规划文件。

## 1. 已与用户确认的目标

1. 优先让算法核心可理解、可验证；同时改善实验可复现性、新算法扩展和仓库技术债。
2. 正确性优先，允许谨慎清理和破坏性变更；不以保留旧错误、旧 RNG 轨迹或旧数字作为最高约束。
3. 精确与近似算法分别立契约：精确路径须符合目标分布；近似路径须明确声明假设、偏差和质量评价，不冒充无偏采样。
4. 范围是整体路线图，以及下一阶段可执行的详细方案。
5. **正确性修复与核心模块拆分同阶段推进**，而非等待全部纠错结束再整理架构；但各批次仍应可独立审查、回滚。
6. 保留主方法、当前消融、活跃独立基线及 CEE-DSD / CEE-DSSD / CEE-CUHLM。旧 `ceesd_without_arp` 及其别名走归档迁移，先核查引用和冻结历史版本，不立即删除。
7. 核心阶段结束前必须有当前版本的真实模型验收；GPU 设备、时间窗口、权重和资源预算另行确认。

非目标：不以某文件降到多少行作为成功标准；不顺带增加批处理服务、重写 RL 训练算法、重训全部权重或追求性能提升承诺。

## 3. 目标架构与不变原则

### 3.1 按职责分层，不建立万能循环

```text
实验配置 / task / runner / 结果与证据
                    ↓
模式注册与解码 runtime（资源装配、生命周期）
                    ↓
各算法族自己的编排（阶段、通信、reward、提交、停止）
           ↙                ↓                ↘
proposal/verification   通信载荷与记账      ARP / RL policy
           ↓
模型 / KV / eager / graph 后端
```

- 算法自己持有循环与拓扑。双模型、三级级联、分裂通信、机会传输保留可见差异。
- 共享的是数学契约、上下文边界、载荷表示和真实复用的原语，不是所有算法的统一执行模板。
- runtime 负责加载和装配，不接管每轮算法顺序。proposal / verification 是结果值，stats 只存数值；不把模型、cache、通信、策略、停止条件塞进一个可变大 context。
- 初期保留现有 Register 的绑定分发，避免重构注册系统扩大风险。算法迁出后，公开入口与已知调用保留有期限的兼容层；不永久承诺兼容包当前泄漏的所有导入名。
- 内部模块通过明确参数/接口协作；不从兼容包反向导入运行依赖，不依赖包级 monkey patch 写透。

建议模块形状（命名可在实施时微调，避免为目录整齐强行迁移）：

```text
src/baselines/
  __init__.py         # 有限兼容入口与装配
  runtime.py          # 模型/权重/策略/缓存资源生命周期
  dual.py             # SD / DSD / DSSD 编排
  adaptive.py         # 两模型 adaptive
  cee.py              # CEE-SD 与当前有效消融
  cee_variants.py     # CEE-DSD / CEE-DSSD / CEE-CUHLM
  protocol_baselines.py # CUHLM / TK-SLT；过大再按真实职责细分
  simulators.py       # 复用已有工厂
```

继续利用已有的验证、采样、通信、model/KV 模块；先改善内容和依赖边界，不同时把全部公共模块改名或换顶级包。

### 3.2 正确性契约

1. **分布身份**：每个 token 的实际生成分布 `q`、传输后的 `wire-q`、验证目标 `p` 都有来源与窗口。不能把旧候选按新 top-k 重新解释，不能用计费开关切换采样 law。
2. **精确路径**：接受概率为 `min(1,p/q)`，均匀随机数使用 `[0,1)` 对应的严格边界；拒绝使用归一化正残差；全接受从正确 bonus 上下文采样。输入支持、非有限数、窗口错位显式失败。
3. **近似路径**：逐模式/配置说明量化或跳过引入的近似，而非按模式名笼统分类。低位宽已有说明见[wire 协议](<cee_sd_body_refactor_20261107.md#L47-L54>)；其他算法须另核论文与实现。机会跳过但最终仍被正确 target 验证，不应仅因名称就认定为有偏。
4. **缓存**：区分已接受 token、已 forward 上下文、已采样未 forward 的 bonus/correction。rollback 对象是实际上下文端点。
5. **停止与预算**：精确路径的候选 EOS 须经最终 target 确认；不会因结束而漏回复/下行/flush；无额外超预算输出。近似协议的停止语义单独声明。
6. **策略**：区分当前生成使用的配置与下一阶段/下一轮配置；ARP 模式真实生效；RL reward 观察时点、更新/冻结和保存边界可测试。
7. **通信与指标**：同协议下记录真实消息种类、字节、链路、NTT 和因果顺序；最终结算之后计算派生指标。不同论文协议不被强制记成同一账。

## 4. 整体路线图

| 阶段 | 主要产出 | 退出条件 |
|---|---|---|
| A：核心正确性 + 模块边界联合收口（下一阶段） | 修复已证问题；拆出 runtime 与首批算法族；SD/DSD/DSSD 共享契约；现有 adaptive/CEE-SD 移至职责清楚的模块；必要的模型前向接口与 graph 身份保护 | CPU 完整门禁、模块边界检查、当前版本真实模型/受支持 graph 验收；未迁移协议族明确标注，不声称全算法验收完成 |
| B：其余活跃算法族与通信契约 | CUHLM、TK-SLT、CEE 组合逐族迁移；共享小型结果值、载荷和计费原语；精确/近似支持矩阵完整 | 每个保留算法完成定义核对、边界测试和对应真实模型验证；近似质量界限有事先批准的实验方案 |
| C：实验工程化与配置 | 单一有效配置、运行快照、task/runner/decoder 组合、版本化结果、统一依赖与自动验证体系 | 同一 manifest 可复跑；不静默忽略参数；任务失败不伪装为零样本成功；新增 task 不再继承整个算法集合 |
| D：兼容层与历史资产收尾 | 旧消融归档、移除无调用旧实现/过期参数、整理文档入口、减少兼容导出 | 每项删除有使用审计、迁移说明与历史复现锚点；新旧结果可识别，文档没有互相冲突的现行规范 |

依赖锁定和最小自动门禁不是等到 C 才做，须在 A 中先具备。C 再完成全实验工程化。阶段是验收边界，不是要求把该阶段全部内容塞进一个 PR。

## 5. 下一阶段 A：详细实施切片

### A0 — 冻结现状、支持矩阵和质量基线

- 给每个注册模式记录：规范名称/别名、活跃或历史、模型拓扑、精确/近似配置、真实使用场景、验收状态。
- 列出共享验证调用者，特别包括仍在 engine 内的入口，以及未迁移的 CEE/CUHLM/TK-SLT；为其建立影响清单。
- 选定并在隔离环境验证一套权威依赖锁；另一安装入口从同源导出或明确不再推荐。锁定 pytest 和选定 lint 工具，先复跑默认/importlib 全量与指纹。
- 建立当前状态索引，旧历史文档保留日期/基点；不覆盖旧结果冒充最新证据。
- 提供最小 CPU 自动门禁。是否接特定远端 CI 平台须依据仓库实际托管权限，不假定已有 branch protection。

### A1 — ARP 独立纠错

- 修复 `per_token` 分支；保留 `cumulative` 和 `threshold=None` 各自语义。
- 覆盖多步、reset、阈值边界、校准映射以及真实 adapter 被生成循环调用的场景，不仅测试参数被保存。
- 单独记录预期行为变化；不把权重重训、阈值重新寻优或 RL 算法改写混入本批。

### A2 — 资源装配与已有算法阶段迁出

- 拆分 runtime 的初始化/模型与权重/策略/缓存生命周期，将已有 adaptive 与 CEE-SD 编排和辅助方法按族迁出。
- 本批以结构迁移为主，保持已修正阶段语义；已有值对象继续使用，不重新发明返回协议。
- 移动时同步迁移测试 patch 目标、注册装配、直接方法访问与必要兼容入口，检查导入顺序、循环依赖、别名映射和 importlib 收集。
- 核对协议能力/参数消费报告。当前内省依赖源码位置和名字，不能通过删除断言来换取迁移通过；若改成显式能力声明，要有真实执行测试防止声明与消费漂移。
- 指纹跨文件 include 与映射变更须评审；不要整体重冻所有模式。

### A3 — 模型/KV 小接口与 graph 配置身份

- 在已有后端提供公开的不采样 forward/extend 及上下文长度接口；生成算法仍自己决定何时采样。
- 用它替代首批迁移路径中的“generate 一次再丢弃 token”，消除对私有前向的依赖。删除额外采样会改变 RNG 轨迹，作为单独语义变更验证，不伪称机械等价。
- graph 缓存复用比较完整有效构造身份；不兼容时明确重建或报错，不复用旧配置。只校验确实影响构造/捕获/采样的字段，避免把逐轮策略动作误当作每轮必须重捕获。
- 明确 batch 支持边界：本阶段不新增 batch>1 支持；不支持的输入显式拒绝，不能只处理第一个样本却伪称批处理成功。

### A4 — SD/DSD/DSSD 契约迁移与算法族拆分

- 先做独立的小词表解析测试，覆盖严格接受、真实 q、零长度、部分/全拒绝、全接受、显式 bonus、缺失/stale 窗口和上下文端点。
- 迁移顺序建议 SD → DSD → DSSD；每种算法同批完成阶段结果值化与迁至目标算法族模块，避免长期只留下“函数搬家”。
- 共享数学验证不持有通信模拟器、RL、args 或整个 decoder；接受判定与采样/缓存提交的副作用边界必须显式。
- DSD 的整段传输与 DSSD 的标量上行/拒绝回传不同，保留在各自编排中；不创建几十个 flag 的统一 round。
- 新版 adaptive/CEE-SD 与共享契约对照验证；仅在真实复用且不增加接口复杂度时接入公共原语，不为消除少量重复强行统一完整阶段。
- 修改共享函数时同时检查全部调用者。若未迁移协议不适配新严格输入，先使用命名明确、调用受限的过渡适配层；禁止无声裁短或隐式 fallback。过渡层列入 B 的删除清单，而非永久双轨。

### A5 — 集成与当前版本真实验收

- 所有结构迁移与纠错合并后，在冻结 SHA 上重跑默认/importlib 全量测试、算法契约、兼容/注册/协议接线、指纹及修改范围 lint。
- 扩展已有 smoke 工具，而非默认其 static-only 配置已经覆盖 adaptive/CEE-SD。保留旧证据 schema 的回放能力。
- GPU 在用户确认设备 UUID、空闲窗口、模型/权重指纹后运行；不自动下载大模型、不覆盖已有 checkpoint、不启动真实在线训练。
- 覆盖本批变更的 SD/DSD/DSSD、两模型 adaptive、CEE-SD 与当前消融；对受支持的路径覆盖 eager/graph，跨样本 reset/复用，以及资源允许的跨设备路径。
- CPU 提供可控拒绝/接受/EOS/预算反例；GPU 提供真实模型/KV/权重接线和数值证据。不能要求随机短 smoke 必然撞中所有罕见分支，也不能用 fake graph 代替 CUDA 执行。
- 如果必需硬件/权重缺失，阶段状态只能为“CPU/结构完成，真实验收待完成”，不能把未执行标为通过。

依赖关系：A0 → A1 / A2；A2 → A3 / A4 的迁移工作；A3、A4 在共享文件上的改动按小批次排序；全部汇入 A5。并行工作必须分配不重叠写入范围，不能多人同时修改整份 core。

## 6. 验收标准：什么才算完成

### 代码与设计

- 首批算法的公开编排能直接读出“提案 → 验证 → 通信/reward → 提交 → 停止”；无需在万能框架和 hooks 间追踪真实顺序。
- 新模块有独立职责与单测入口；runtime 不重新长成持有所有轮内变量的大对象。
- 已知两个确定缺陷有先失败后通过的回归测试；共享窗口、bonus、rollback 与其他调用者的影响逐项可说明。
- 没有为行数、指纹或旧 fixture 改写数学契约；没有整体放松测试。

### 数学与统计

- 精确路径：小词表解析/枚举验证为基础，随机测试为补充；目标分布包含指定 temperature/top-k/top-p 处理，不能比较不同采样设置。
- 贪心路径：同模型、tokenizer、有效采样配置和受控数值后端下，与 target-only 比对输出；如出现差异，定位近似路径、数值误差或实现问题，不简单当成时间噪声。
- 随机路径：同 seed 不意味着不同采样流程的 token 必须相同。依据独立算法契约和预先设计的统计检验，不以“检验未拒绝”声称数学证明。
- 近似路径：质量指标、样本量和容许退化在正式实验前确认；在预算未定前只报告测量，不称质量已达标。

### 证据与性能

- 每次正式验收关联 commit、命令、最终有效配置、依赖环境、设备 UUID、模型/tokenizer/ARP/RL 指纹、原始输出和比较报告。
- 冻结旧 oracle/golden 仍用于解释变化，但错误行为修复不能被旧 golden 否决；只更新受影响的预期，附逐项理由。
- 确定性通信账核对精确值；wall time/吞吐使用受控配对重复测量，性能容忍区间在基线校准后确定，不凭空指定百分比。
- 真实 RL 权重的冻结推理与在线训练不是同一验收。当前阶段检查策略输入、动作应用、reward 时点及更新/保存门控；不宣称完整训练数值轨迹或收敛已验证。

## 7. 兼容与归档规则

- 保留常用 Baselines 导入、活跃模式名和结果读取能力作为迁移桥梁；内部 helper、patch 目标可随职责调整并同步更新调用方。
- 输出新增协议/算法语义版本，避免同一个模式名下的新旧实验数字无标识混合；历史 raw 工件只读保留。
- 旧 `ceesd_without_arp` / `ceesd_w/o_arp`：盘点脚本、论文实验、测试与外部使用 → 记录冻结 commit/权重/命令 → 给出与当前 `cee_sd_no_arp` 的差异说明 → 提醒/迁移 → 经确认退出活跃注册。不能简单静默重定向，两者并非等价消融。
- CEE 组合方法保持活跃范围，不借整理目录之名删除；其专门的算法/通信契约在 B 完成。
- 不自动删除模型、checkpoints、实验输出、第三方子项目或用户未跟踪文件。

## 8. 实施前仍需确认的操作条件

目标和联合推进方向已确定；以下不妨碍确定方案，但在执行相应步骤前必须确认：

1. 开发分支/worktree、是否有运行中的实验，以及允许切换运行代码的窗口。
2. 正式 GPU 设备/时间、可用模型与真实 ARP/RL 权重、是否支持计划中的跨设备配置。
3. 真实统计验收的样本预算、近似协议的质量阈值及性能回归预算。
4. 旧模式实际调用者与兼容期，以及破坏性接口变更的逐项迁移清单。

本次结论不是“所有算法已正确”，而是已经找到了明确的纠错和边界收敛路径。整轮重构的终点是：**保留的每个算法有明确规范、可验证阶段、可信实验身份和与其支持范围相称的真实运行证据**。
